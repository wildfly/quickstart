= dynamic-client-ssl-context: Dynamic client SSL Context between Server and Client
:author: Richard Záň
:level: Intermediate
:technologies: Dynamic TLS, Security, Undertow

[abstract]
The dynamic-client-ssl-context quickstart shows the option to select different SSL/TLS configurations dynamically based on the host and port of the outbound connection.

:standalone-server-type: default
:archiveType: war

== What is it?

Elytron client supports dynamic client SSL context. It can be configured everywhere in the subsystem where client-ssl-context attribute can be configured.

The `dynamic-client-ssl-context` quickstart demonstrates enabled dynamic SSL context for specified URLs and their ports. The only function they represent is to be called via provided REST client and pass a successful call through the SSL/TLS configuration.

[[configure_the_server]]
== Configure the Server

You configure the dynamic client SSL context and its dependencies/configuration by running JBoss CLI commands. For your convenience, this quickstart batches the commands into a `configure-dynamic-client-ssl-context.cli` script provided in the root directory of this quickstart.

. Before you begin, make sure you do the following:

* xref:back_up_standalone_server_configuration[Back Up the {productName} Standalone Server Configuration] as described above.
* xref:start_the_eap_standalone_server[Start the {productName} Standalone Server] as described above.

. Review the `configure-dynamic-client-ssl-context.cli` file in the root of this quickstart directory. This script adds the configuration that enables selecting different SSL/TLS configurations dynamically based on the host and port of the outbound connection for the quickstart deployment.
Comments in the script describe the purpose of each block of commands.
. Open a new terminal, navigate to the root directory of this quickstart, and run the following command, replacing `__{jbossHomeName}__` with the path to your server:
+
[source,subs="+quotes,attributes+",options="nowrap"]
----
$ __{jbossHomeName}__/bin/jboss-cli.sh --connect --file=configure-dynamic-client-ssl-context.cli
----
+
NOTE: For Windows, use the `__{jbossHomeName}__\bin\jboss-cli.bat` script.
+


[[review_the_modified_server_configuration]]
=== Review the Modified Server Configuration

There are too many additions to the configuration file to list all of them here.
It is recommended to look into these quickstarts, which have similar SSL setup configuration.:

. xref:../helloworld-mutual-ssl-secured/README.adoc#review-the-modified-server-configuration[helloworld-mutual-ssl-secured Server configuration] for more information.
. xref:../helloworld-mutual-ssl/README.adoc#review-the-modified-server-configuration[helloworld-mutual-ssl Server configuration] for more information.

As another source of information, `configure-dynamic-client-ssl-context.cli` script has detailed description for each step.

To highlight the most important changes it would be recommended, after the server was stopped, opening the `__{jbossHomeName}__/standalone/configuration/standalone.xml` file to review the changes.

. Two of the following `key-store` entries was added to the `elytron` subsystem:
+
[source,xml,options="nowrap"]
----
<key-store name="twoWayKS1">
    <credential-reference clear-text="secret"/>
    <implementation type="PKCS12"/>
    <file path="server1.keystore.P12" relative-to="jboss.server.config.dir"/>
</key-store>
<key-store name="twoWayTS1">
    <credential-reference clear-text="secret"/>
    <implementation type="PKCS12"/>
    <file path="server1.truststore.P12" relative-to="jboss.server.config.dir"/>
</key-store>
----

. One of the following `key-manager` entries was added to the `elytron` subsystem:
+
[source,xml,options="nowrap"]
----
<key-manager name="twoWayKM1" key-store="twoWayKS1">
    <credential-reference clear-text="secret"/>
</key-manager>
----

.  One of the following `trust-manager` entries was added to the `elytron` subsystem:
+
[source,xml,options="nowrap"]
----
<trust-managers>
    <trust-manager name="twoWayTM1" key-store="twoWayTS1"/>
</trust-managers>
----

. The `server-ssl-context` was updated to reference the new `trust-manager` entries to enable two-way TLS:
+
[source,xml,options="nowrap"]
----
<server-ssl-contexts>
    <server-ssl-context name="twoWaySSC1" need-client-auth="true" key-manager="twoWayKM1" trust-manager="twoWayTM1"/>
</server-ssl-contexts>
----

. Similarly `client-ssl-context` was updated to reference the new `trust-manager` entries:
+
[source,xml,options="nowrap"]
----
<client-ssl-contexts>
    <client-ssl-context name="client1-ssl-context" key-manager="clientKM1" trust-manager="clientTM1"/>
</client-ssl-contexts>
----

. `dynamic-client-ssl-contexts` was enabled:
+
[source,xml,options="nowrap"]
----
<dynamic-client-ssl-contexts>
    <dynamic-client-ssl-context name="dynamicClientSSLContext" authentication-context="ac"/>
</dynamic-client-ssl-contexts>
----

[[access_the_application]]
=== Access the Application

The application will be running at the following URL: http://localhost:8080/dynamic-client-ssl-context

A main page displays list of links:

[source,options="nowrap"]
----
Click below to send request to different ports:

Send request to port 9443
Send request to port 10443
----

Each of links calls specific endpoint on server and the server's endpoint executes https GET request under specified ports. Each port uses a different TLS certificate. Both GET requests use the same dynamic client SSL context. For http://localhost:8080/dynamic-client-ssl-context/rest/port9443request, it will display:

[source,options="nowrap"]
----
HTTP status of result is 200
----

Similar result is for http://localhost:8080/dynamic-client-ssl-context/rest/port10443request:

[source,options="nowrap"]
----
HTTP status of result is 200
----

Internally, this quickstart calls the following two URLs, each with enabled dynamic SSL context:

[cols="100%",options="headers"]
|===
|URL paths with their ports

|`https://localhost:9443/dynamic-client-ssl-context/`

|`https://localhost:10443/dynamic-client-ssl-context/`

|===

The server configuration is done using CLI batch scripts located in the root of the quickstart folder.
